# 路线图与待办（Roadmap）

> 面向"下一步做什么"：按优先级排序，每条都有**验收标准**，做完请回到 [DECISIONS.md](./DECISIONS.md) 补一条 `A-xx` 动作记录。
> 优先级定义：**P0** = 影响核心体验/有明确用户感知缺陷；**P1** = 提升可维护性与完成度；**P2** = 锦上添花或依赖外部条件。

## 2. P0：下一轮优先（核心体验）

### R-01 角色 ↔ Live2D 模型绑定（多模型 / 换装）
- **现状**：5 个角色共用 Haru 一个模型，切换角色只有文案/配色/音色变化，视觉上"还是同一个人"。
- **做法**：`models` 配置化（`config/models.js`：id / path / scale / offset / 所属角色）；`Live2DView` 支持 `loadModelByIndex` 或重建实例；切换时先 `stage.unMount()` 再挂载，避免画布叠加。
- **验收**：切换 5 个角色，模型随之切换；连续切换 20 次后 `document.querySelectorAll('canvas').length === 1`，内存无明显增长。
- **前置**：需要可商用的模型素材（当前仅 Haru，注意 Live2D 官方样例的许可范围）。
- **工作量**：M（半天~1 天，含素材准备）

### R-02 音素级口型同步
- **现状**：口型是正弦模拟 + TTS boundary 脉冲，观感"在动"但不对音节。
- **做法**：接入可返回音素/时间戳的 TTS（Edge TTS 的 `WordBoundary`、GPT-SoVITS、或 Azure Speech）；把音素映射到 `ParamMouthOpenY` + `ParamMouthForm`（元音 a/i/u/e/o → 口型开合与形状）。
- **验收**：朗读"你好呀，今天过得怎么样"时，口型开合次数与音节数一致（录屏逐帧抽查 ≥ 80% 吻合）。
- **工作量**：L（2~3 天，取决于 TTS 选型与网络条件）

### R-03 流式渲染性能（Markdown 增量 + 节流）
- **现状**：每个 content chunk 都触发整条消息的 `parseBlocks` 重算（`Markdown.jsx` 的 `useMemo` 依赖整个 text）。3000 字回复的流式期间会有明显掉帧。
- **做法**：① 流式期间以纯文本 + 光标渲染，结束后再做一次 Markdown 解析；或 ② 按"已闭合的块"增量解析（只解析到最后一个换行）；③ 用 `requestAnimationFrame` 合并 60ms 内的多次更新。
- **验收**：注入 3000 字 SSE 文本，DevTools Performance 面板中主线程长任务 < 50ms，帧率 ≥ 50fps。
- **工作量**：S（2~3 小时）

### R-04 语音打断（barge-in）
- **现状**：朗读中用户说话不会停止 TTS，两个声音打架。
- **做法**：`useSpeech` 检测到 `onresult`（哪怕 interim）→ `tts.cancel()`；同时把 `speaking` 置 false，Live2D 闭嘴。
- **验收**：朗读中点麦克风说话，TTS 在 300ms 内停止。
- **工作量**：S

### R-05 消息编辑与对话分支
- **现状**：只能"重新生成"最后一条，不能改自己说过的话。
- **做法**：用户气泡 hover 出"编辑"，确认后截断该消息之后的所有消息 + 重新发送（复用 `useChat.regenerate` 的截断逻辑）。
- **验收**：编辑第 2 条用户消息并重发，第 3 条及之后的回复被替换，历史记录保持一致。
- **工作量**：S~M

## 3. P1：工程化与完成度

### R-06 自动化测试与 CI
- **现状**：无任何测试；本次重构依赖临时 jsdom 脚本（未入库）。
- **做法**：
  - 单测（Vitest）：`Markdown` 解析、`EmotionBuffer`、`calculate` 安全求值、`toHistory` 截断、SSE 分帧器；
  - 组件测试（Testing Library）：Composer 快捷键、Settings 开关、tool 气泡排序；
  - E2E（Playwright）：首屏渲染、发一条消息、停止生成、切换角色后历史隔离；
  - CI：GitHub Actions 跑 `lint + test + build`（后端 `pytest` 跑工具与路由）。
- **验收**：PR 上 CI 全绿；覆盖率 ≥ 60%（核心模块 ≥ 80%）。
- **工作量**：M~L

### R-07 历史消息治理
- **现状**：`avatar-chat.history.<persona>` 无上限；超出 5MB 后写入静默失败。
- **做法**：保留最近 200 条；更早的消息折叠为"更早的 N 条对话"可展开 / 或直接丢弃并提示；写入失败时 Toast 提示。
- **验收**：连续发 500 条后刷新，最近 200 条完整、无报错、localStorage 占用 < 2MB。
- **工作量**：S

### R-08 长对话的"记忆压缩"
- **现状**：只带最近 12 轮，更早的上下文丢失。
- **做法**：当轮数超过阈值时，后端（或前端触发一次独立请求）把更早的对话摘要成 3~5 句放进 system prompt，附"以下是此前对话摘要"。
- **验收**：聊 30 轮后仍能正确回答"我最开始说我叫什么"。
- **工作量**：M

### R-09 网络异常重试与可观测性
- **做法**：SSE 中断（非用户主动停止）时提示"连接中断，点击重试"；后端记录 request_id + 耗时 + 工具名 + token 用量；前端把错误分类（后端未启动 / 未配置 Key / 限流 / 超时）。
- **验收**：kill 后端进程后发送消息，提示为"连不上后端服务"，点击重试后恢复成功。
- **工作量**：S~M

### R-10 PWA 与移动端手势
- **做法**：`manifest.json` + Service Worker 缓存静态资源；移动端支持双指缩放模型、单击切换场景。
- **验收**：手机可"添加到主屏幕"并离线打开 UI（对话仍需后端）。
- **工作量**：M

## 5. 技术债清单（不排版本，但改到相关代码时应顺手处理）

| 债务 | 位置 | 说明 |
| :--- | :--- | :--- |
| 依赖库私有结构 | `Live2DView.jsx` `getCoreModel()` | 用 `instance.models.model.internalModel` 取参数，升级 oh-my-live2d 时需回归 |
| 无类型检查 | 全前端 | 纯 JS；可渐进迁移 TS（先 `services/` 与 `hooks/`） |
| 无鉴权/限流 | `main.py` | 仅适合本机/内网；公网部署前必须补 |
| CSS 体积 | `styles/*` | 28KB 未压缩分离，可进一步按页面拆分 |
| 图像生成强依赖第三方 | `image_gen.py` | Pollinations 无 SLA；建议加"最近成功时间"健康标记 |
| 离线模式文案写死 | `services.py` | 可改为按角色定制（读取 persona 的 greeting） |
| `body.json` 示例易过期 | 根目录 | 可改为从 `docs/` 生成或删除，避免与 schema 漂移 |

## 6. 如何维护本文档

1. 新想法先加到对应优先级段落，写清**验收标准**（否则无法判断是否完成）；
2. 开始做时把 ID 标 `🚧`，完成后移到"已完成"并链接 `DECISIONS.md#a-xx`；
3. 放弃的想法移入 `DECISIONS.md` 的"未采纳方案"（`N-xx`），保留原因。
